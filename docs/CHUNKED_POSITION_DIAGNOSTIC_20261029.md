# Sparse workspace position attribution

Register before any quality score or selection in the current sparse-persistent
screen. This is a separate CPU-only supplement, not a change to that screen.
Run only after all nine fits, audits, selection, exact readout and main analysis
complete, and the Native owner closes. Use the same selected checkpoints and
all 384 original DEV sources. Neither fresh reserve is opened.

Partition each 512-target view using only its fixed position. The five bins are:
127 targets before the first slot; four predictions emitted by slots; 24 targets
at offsets 1–8 after earlier slots; 72 at offsets 9–32; and 285 at offsets 33–127.
Every target appears exactly once. Compare generated versus ordinary and trained
constant slots in every bin, with web/math/code and the original 60/20/20 weights.
Report each bin's contribution to the original broad gain. All contributions
must reconstruct that gain. First reproduce the original whole-panel scores
within 1e-8 nats; failed reconstruction invalidates the supplement.

There is no new advancement gate. These conditional source-group intervals use
2,000 bootstrap draws, seed 40514, and are descriptive, unadjusted diagnostics.
They neither repair a failed broad comparison nor establish training-seed
uncertainty. No bin, domain, endpoint or learning rate is selected for a claim.

Only if both original development gates pass, additionally evaluate the generated
model with access to earlier latent keys blocked. Preserve the current latent
slot's self attention and all source keys and positions. Recompute all downstream
states using the independently tested full-prefix reference. Each CPU worker
checks authentic cached/reference agreement on one full context in every domain,
and checks that blocking has no effect on the first 128 predictions. Maximum
log-probability discrepancy is 1e-8. Evaluate the entire panel, not a favorable
subset. Blocking is outside the trained distribution: degradation demonstrates
dependence on a removed memory path, not reasoning or a valid zero-budget model.

Use four CPU workers with eight threads each, six GiB maximum RSS per worker,
the existing host/disk reserves, zero chips and zero optimizer updates. Allow at
most 20 minutes, with an absolute deadline 20 minutes after the original screen's
deadline. No automatic retry or promotion. Source hashes are frozen now; selected
checkpoint hashes are bound to their completed independent audits at admission.
Keep individual source metadata and losses private; publish aggregate comparisons,
hashes, validation and costs. This design adds no training opportunities.
