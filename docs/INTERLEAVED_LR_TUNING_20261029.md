# Persistent-state development tuning — prospective registration

This bounded random-initialization discovery screen follows complete actual-
shape qualification of the generated-state, pause and ordinary execution paths.
It is not the full from-scratch learning-age campaign, confirmation, an adaptive
compute claim or a reinterpretation of prior negative results.

Use51,747,328 parameters, six512-wide blocks, eight attention/KV heads, SwiGLU1376,
independent32k input/output tables,512 natural source positions, FP32 and64 ranks
with two windows per rank. The grouped storage layout is an equivalent
permutation of the original chronological computation. Its full qualification
records100 warm updates at0.24634s, mature family gradient errors below1.09e-6,
all-replica equality and exact full-state restart replay. The pause and ordinary
reports must independently pass before admission; pin all three receipts.

Three families receive exactly the same tuning opportunities: ordinary NTP,
NTP with generated persistent states, and NTP with trained constant pause states.
Each starts from the same fresh seed9901 and sees the same first at-least128M
real targets from the accepted six-billion-position index. Use learning rates
{0.0003,0.001,0.003}, AdamW betas(0.9,0.95), epsilon1e-8, weight decay0.1,
global clipping1,64-update warmup, stable LR, and a final10% cosine cooldown to
0.1 of peak. Round to whole global updates and record exact real-target counts.
Each authentic target receives one uniform NTP loss; no latent-position labels.
The generated arm uses one latent slot/source and two fixed Jacobi refinements.
The pause arm uses the shared table mean as its constant input; it does not
execute the generated-state passes. Count its cheaper actual work.

Every fit has a complete endpoint state, all-replica checks and an independent
128-window global gradient audit before any predictive scoring. Numerical audit
windows begin at index10,000,000, outside all fitted tuning prefixes. No source
wrapping. All source/index/tokenizer hashes are pinned. Fresh reserved source
groups remain unscored and are excluded from training.

Select each family's LR by minimum fixed60/20/20 broad development NLL across
384 existing source-separated windows; exact ties choose lower LR. Do not use
the dependency panel for tuning. If the selected LR is at a grid boundary,
register one outward setting at the same budget before calling it bracketed;
there is no automatic main fit or open-ended LR extension. Selection on this
reused panel is explicitly development evidence, not confirmation or an
unbiased post-selection estimate.

The immutable execution plan caps the entire queue at four hours and each
Native phase at30minutes, CPU phases at20minutes. A0.8-second warm-update ceiling
stops unexpected execution regression. Use all16 existing chips per qualified
Native phase. Maintain512GiB host,35GiB disk and10,000 inode reserves, with a
12GiB artifact allowance and complete snapshot projection. Account for tuning,
compilation, checkpointing, audits, evaluation and failed work separately.

Only after this screen may a new finite protocol select complete longer
endpoints, equal-work ordinary training and stronger conventional alternatives.
A prediction improvement is not automatically transferable reasoning; generated
content, sequential-execution agreement and natural dependency generalization
remain separate tests. No useful-effect threshold or failed historical result
is changed here.
