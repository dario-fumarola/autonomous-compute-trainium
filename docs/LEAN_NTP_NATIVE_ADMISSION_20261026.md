# Conditional native qualification of lean NTP

This implements the gate fixed in the lean preparation before any new main
outcomes. Wait without chips for the entire five-endpoint fixed-control study,
including all independent scoring and gradient audits. Preserve its original
clock. A stopped predecessor never authorizes this follow-up.

Proceed only when both training seeds favor recurrence against each work
control and both two-seed mean gains reach 0.01 nats. Recompute this from all
six frozen contrasts, without rounding or selecting a favorable control. A
failed development gate ends this queue with zero native work. It does not
change the predecessor's conclusions or spend confirmation alpha.

If eligible, admit only the prepared numerical qualification: deterministic
one/two fully differentiated passes, original qualification-only initializer,
FP16 body, primitive FP32 attention, FP32 head/masters/moments, manual scale
8192, and the existing changing 1e-4 qualification schedule/runtime optimizer.
The unused auxiliary head and loss are absent. The old worker selector
`poisson2` receives the frozen all-(2,2) table; no depth sampling occurs.

Use the existing 121-update warm and one-update fresh-process replay engines,
with explicit owned non-ephemeral communication ports. A thin outer wrapper
validates the exact phase, source list, preparation, plan and resume checksum.
It leaves the already frozen constructor/preparation unchanged. Both warm
profiles run on separate eight-chip halves, with CPU checks overlapping replay.
No shared container cleanup and no change to the running scientific workers.

Require all-replica equality, initial local gradients, full 512-window trained
gradients against pinned upstream CPU FP32, independent first optimizer steps,
exact restored full state/RNG, and the existing 2% named update/moment replay
gate. Compare replay gradients against the same independent CPU vector too.
Report bit equality separately; this does not promise identical future paths.
Reject unexpected fallbacks, nonfinite values, missing phases or failed gates.

Freeze a one-hour qualification clock only after admission. Bound each native
phase to 900 seconds and CPU phase to 1,200 seconds. The complete estimate uses
the slower measured full-head 100-update rate with a 50% margin, four cold
launches, two independent CPU audits and replay checks. Require at least 65 GiB
free on NVMe before admission, plus the protected 35 GiB filesystem, 512 GiB
available-memory and 10,000-inode reserves. Count 244 qualification updates,
extra probes, CPU optimizer steps, all failures and setup/scoring tails. Saved
successful closures can be reused after controller recovery, while the
original clock and exact saved source/path lists remain fixed. Partial phases
require an explicit recovery registration, not an automatic rerun.

The queue's latest admission time is the predecessor's original deadline plus
600 seconds. Waiting uses zero chips; do not add its elapsed time again to the
predecessor's instance reservation. Qualification costs start at qualification
admission and remain separate from that waiting interval.

Stop after numerical/throughput qualification. This admits no LR search,
scientific fit, adoption of qualification weights, held-out quality readout,
TEST access, reserve access or terminal alpha. A lean scientific comparison
would need original random scientific weights, complete matched work and its
own measured frozen budget. The research objective remains unachieved here.
