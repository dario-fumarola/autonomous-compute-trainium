# Prepare a bounded native check of lean next-token training

The completed CPU check shows that deleting the zero-weight auxiliary head
preserves the checked prediction loss, gradients and first optimizer update.
It removes 24,608,000 unused training parameters. This alone does not qualify
native headless training or justify repricing any completed model history.

Prepare a separate numerical check while the fixed-control replication runs.
Use zero accelerator chips during preparation. Change no frozen source or
worker in that campaign. This preparation does not admit a native job.

Reuse the existing complete lean Parcae qualification trainer and independent
pinned-upstream checker, with an explicit wrapper selecting the already checked
FP32 primitive-attention body and runtime-scalar optimizer. Keep FP16 body,
FP32 vocabulary head/masters/moments, manual loss scale 8192, global 512 natural
windows, accumulation 16, and the same 2/2/2 model. The auxiliary projection,
loss and parameter inventory are absent. Count the real next-token projection,
attention, full backward and all 32 replicated optimizer matrix updates.

Two qualification cases execute deterministic depths one and two, with full
gradients. The old worker's CLI selectors are `fixed1` and `poisson2`; the latter
is only a legacy selector here. Its prepared table is uniformly (2, 2), never a
Poisson sample. Preserve that distinction in all public summaries.

Use the original qualification-only seed-1009 initializer, not a trained
checkpoint. The new preparation references its immutable existing file, and
the independent CPU auditor uses that very same initializer. Both bodies have
141,963,840 parameters. Qualification states remain ineligible for science.

A future warm phase performs 121 updates, measuring exactly updates 21–120;
a separate fresh-process replay performs update 121 from the full update-120
checkpoint. The existing changing qualification schedule peaks at 1e-4, with
the same first-update schedule as the original independent optimizer checker.
This is a conservative numerical/throughput schedule, not LR selection or
evidence that 1e-4 is a good scientific learning rate. The runtime-scalar
optimizer has already been checked at the scientific selected rates separately.

Before a scientific lean fit, require complete global gradients against CPU
FP32, the independent first optimizer-step check, all-replica equality, exact
loaded optimizer/model/RNG state and the registered 2% update/moment replay
criterion. Report bit equality separately; do not promise identical future
trajectories. Require actual 100-update timings and a separately measured
scientific budget. No new operators or numerical tolerances are introduced.

At preparation, check exact original source, initializer and corpus identities,
both fixed-depth tables and exact work ledgers. The existing CPU parity receipt
is a prerequisite, not a new result produced by metadata preparation. The
legacy-compatible CPU marker records this inheritance explicitly.

Do not launch native qualification while the current main comparison owns the
instance. Before its outcomes, declare that the lean follow-up is warranted only
if both seed-specific recurrent gains are positive against each work control
and both two-seed mean gains are at least 0.01 nats. Otherwise retain the lean
preparation without native expenditure. This is a DEV resource-allocation gate,
not confirmation or a change to the running experiment's analysis.

Any eventual qualification admission needs its own fixed one-hour cap, phase
bounds, complete costs and at least 65 GiB NVMe free in addition to the usual
512 GiB available-memory / 35 GiB filesystem / 10,000-inode guards. Preserve
failed and stopped work. No learned state, held-out quality result, TEST access,
reserve access, terminal alpha or large fit is authorized by this preparation.
