# Closed duplicate storage recovery

Thirteen completed historical checkpoint copies are replaced by exact ZIP
payload-sharing archives. Their original binaries total11,190,049,331bytes;
the new recipes and literal payloads total394,809bytes. Every original hash
and byte length is reconstructed before removing its duplicate path, and a
materialized restoration also passes. Required raw parent files remain.

The11,189,654,522byte difference is logical duplicate storage, not an isolated
measurement of filesystem blocks released: shared links and concurrent active
artifacts affect free space. The closing filesystem reports49,989,414,912bytes
free. No source tokens, model values, optimizer values or execution evidence
are discarded; legacy readers must restore a raw checkpoint before opening it.

The first attempt stopped on a root-owned historical directory and released
zero files after16.146seconds. This separately recorded ownership-only recovery
keeps its exact selection and original deadline, taking111.514seconds. All955
sources bound by the active scientific controller remain unchanged. Both
attempts use zero chips and zero optimizer updates.
